# 🎁 카카오 선물하기 체험단 자동 신청 (모바일 에뮬레이션)

카카오톡 **선물하기 체험단**을 아이폰(모바일)처럼 접속해서, 신엽 님 기준에 맞는 상품을 **몇 개 신청할지 골라서** 자동으로 신청해 주는 프로그램입니다.
신청 성공 건은 **노션 현황표(`🎁 카카오 체험단 응모 현황표`)에 자동 기록**됩니다.

실행은 **`run.bat` 더블클릭 하나**입니다. 설치 확인 → 웹 조종판이 자동으로 열리고, 로그인·담당자 열 선택·미리보기·자동 신청을 **한 화면**에서 합니다.
검은 창 명령이 필요하면 `scripts\run_auto.bat` (자동화·배치용)을 쓰면 됩니다.

- 컴퓨터: **윈도우** (맥·리눅스도 동일하게 동작)
- 준비물: 파이썬(Python) 1개, 카카오 계정 1개
- 로그인 비밀번호는 **어디에도 저장되지 않습니다.** 브라우저 프로필(`kakao_profile` 폴더)과 세션 백업(`kakao_state.json`)에 로그인 상태만 남습니다.

---

## 1. 처음 한 번 — `run.bat` 하나만 있으면 됩니다

### 1-1. 파이썬 설치 (윈도우)
1. https://www.python.org/downloads/ 접속 → **Download Python 3.x** 클릭
2. 설치 파일 실행 → **맨 아래 "Add python.exe to PATH" 체크박스를 반드시 체크** → Install Now

> 맥·리눅스는 터미널에서 `./run.sh` 를 쓰면 됩니다(파이썬3가 이미 있는 경우가 대부분).

### 1-2. 이 폴더 내려받기
- GitHub 페이지 오른쪽 위 **Code → Download ZIP** → 압축 풀기 (예: `C:\kakao-gift-trial-auto`)
- 압축을 푼 폴더 안에 **`run.bat` 하나만 보이면 정상입니다.**

### 1-3. `run.bat` 더블클릭 — 설치까지 자동
- **`run.bat` 을 더블클릭** 하세요. 그게 전부입니다.
- 처음 한 번은 검은 창이 뜨고 **필요한 프로그램과 브라우저를 알아서 내려받습니다.** (3~10분, 인터넷 필요)
  - 이미 설치돼 있으면 이 단계는 **건너뛰고** 바로 열립니다.
- 끝나면 브라우저에 **웹 조종판**(`http://127.0.0.1:8765`)이 자동으로 열립니다.
- 파이썬이 없으면 창에 설치 안내(주소·PATH 체크)가 나옵니다.

> 설치 중 빨간 글씨(에러)가 보이면 그 화면을 캡처해서 알려 주세요.

## 2. 최초 1회 로그인 (웹 조종판에서)

1. 조종판 위쪽의 **[카카오 로그인 창 열기]** 를 누릅니다.
2. **데스크톱 크기의 브라우저 창**이 열리고 카카오 로그인 화면으로 이동합니다.
3. 창 안에서 **카카오 로그인**을 끝까지 진행합니다. (카카오톡 QR 로그인 / 아이디 로그인 모두 가능)
4. 로그인이 끝나면 **자동으로 감지**됩니다. (2초마다 확인, 최대 3분 · 검은 창에서 **Enter** 로 즉시 확인)
5. 조종판 위쪽 표시가 **“로그인됨 · 닉네임”** (예: `로그인됨 · 서브.오 (ID …4821)`) 으로 바뀌면 끝입니다. 그대로 3번(미리보기 → 자동 신청)으로 이어가면 됩니다.

> 로그인 상태는 보통 몇 주간 유지됩니다. “로그인 필요”로 바뀌면 위 1번을 다시 하면 됩니다.
> 배지의 **닉네임**은 지금 세션으로 gift.kakao.com 헤더 API(`/a/v1/header`)를 불러 읽은 그 계정의 이름입니다. 닉네임 뒤 괄호의 **ID 끝 4자리**는 계정 고유 번호를 가린 것으로, 닉네임이 같은 두 계정도 이걸로 구분합니다. 닉네임을 읽지 못하면 `ID …1234` 만 보입니다.

### 2-1. 로그아웃 · 다른 계정으로 로그인
- 조종판 위쪽 **[카카오 로그아웃]** 을 누르면 저장된 로그인 세션(쿠키 백업 + 브라우저 프로필)을 지우고, 상태가 **“로그아웃됨 — 다시 로그인해 주세요”** 로 바로 바뀝니다.
- 그다음 **[카카오 로그인 창 열기]** 로 **다른 계정**에 로그인하면 됩니다.
- **계정을 바꾸면 배지도 새 계정 닉네임으로 바뀝니다**(예: `로그인됨 · 서브.연` → `로그인됨 · 서브.오`). 이 닉네임으로 지금 어느 계정인지 한눈에 확인하세요.
- 신청 이력(이미 신청 N건)은 **그 계정의 세션으로 다시 읽습니다.** 이전 계정의 쿠키를 물고 있지 않으므로, 계정을 바꾼 뒤 미리보기의 “이미 신청 N건 제외”도 새 계정 기준입니다.
- 검은 창에서는 같은 일을 `python main.py --logout` 으로 합니다.
- 자동 신청이 도는 중이거나 로그인 창이 열려 있으면 로그아웃은 거부됩니다(먼저 [중단] 또는 창 닫기).

### 2-2. (드물게) 모바일 화면에서 세션이 인식되지 않을 때

```bat
python main.py --login-mobile
```

데스크톱 창 대신 **모바일(iPhone) 화면**에서 같은 로그인을 진행합니다. 로그인 주소는 자동으로 뜨는 것을 그대로 쓰면 됩니다.

> ⚠️ **체험단 화면 안에서 로그인하지 마세요.** 체험단 페이지는 모바일 전용이라 모바일 화면으로 열리는데,
> 그 화면의 로그인 버튼은 **카카오톡 앱으로 열기**로 연결됩니다. PC에서는 앱이 열리지 않아 로그인이 끝나지 않고,
> "카카오 계정으로 로그인하기"로 계정에 들어가도 **선물하기 로그인 상태는 만들어지지 않습니다.**
> 그래서 로그인만은 데스크톱 창에서 합니다. 로그인한 세션은 신청(모바일 화면)에서 그대로 이어집니다.

## 3. 매번 사용 — `run.bat` 하나로 끝

**`run.bat` 더블클릭 → 브라우저에 조종판이 열립니다.** 로그인 · 담당자 열 · 모드/개수 · 미리보기 · 자동 신청이 **한 화면**에 있습니다.

1. 위쪽 **[카카오 로그인 창 열기]**(처음 한 번) → 상태가 **“로그인됨 · 닉네임”** 인지, 그 닉네임이 이번에 쓸 계정(예: `서브.오`)인지 확인
2. **기록할 담당자 열**을 고릅니다 — 노션 토큰·DB ID 는 **한 번 저장하면 다시 묻지 않습니다.** 고른 열은 다음 실행의 기본값으로 기억됩니다.
3. 모드(노션 미체크 목록 / 카카오 전체 중 신청 안 한 것)와 개수를 고르고 **[후보 목록 불러오기]**
   - 개수는 숫자를 직접 넣거나 **[50개] [100개] [200개] [전체]** 칩을 누르면 됩니다. **`0` 또는 [전체] = 있는 것 전부**
4. **[자동 신청 시작]** → 로그 창에 진행 상황이 흐르고, 끝나면 성공/스킵/실패·노션 기록 건수가 표시됩니다.

- 조종판이 열리지 않으면 주소 `http://127.0.0.1:8765` 를 브라우저에 직접 입력해 보세요.
- 조종판은 **이 PC 안에서만** 열립니다(같은 와이파이의 휴대폰에서도 접속 안 됨). 끄려면 검은 창을 닫거나 `Ctrl+C`.

### 3-1. 화면 구성

| 위치 | 내용 |
|---|---|
| 상단 | **카카오 로그인 상태 + 지금 계정 닉네임**(`로그인됨 · 서브.오`) · [로그인 확인] · **[카카오 로그인 창 열기]** · **[카카오 로그아웃]** |
| 노션 연동 | **“노션 설정 저장됨”** 표시 + **이번에 기록할 담당자 열** 선택(직전 선택 기억) + **[↻ 새로고침]**. 토큰·DB 는 **▸ ⚙ 설정 변경** 접힘 메뉴에서만 바꿉니다(처음 한 번 · **토큰만 넣으면 DB 자동**, 여러 DB 면 [연결된 DB]에서 선택, [↻ DB 목록]으로 다시 찾기). [노션 기록 끄기]도 그 안에 있습니다. |
| 실행 설정 | 모드(노션 미체크 목록 / 카카오 전체 중 신청 안 한 것) · 신청 개수 + **[50개][100개][200개][전체]** 칩(`0 = 있는 것 전부`) · 정렬 · [신청 완료하기] 직전 대기(초) · 친구공개 위시 담기 · 카테고리 미확인 포함 |
| 미리보기 | [후보 목록 불러오기] → 상품명·브랜드·신청/모집·마감·카테고리 표 + “노션 DB 519행 … → 신청 대상 244건” 요약 |
| 실행 | **[자동 신청 시작]** / [중단] · 실시간 진행 로그 · 끝나면 성공/스킵/실패·노션 기록 건수 |

- **[중단]** 은 지금 신청 중인 상품 1건을 마친 뒤 멈춥니다(중간에 끊어 실패하지 않도록).
- 로그인 창은 조종판이 직접 띄웁니다(`scripts\run_login.bat` 과 같은 창). 로그인을 마치면 상태가 자동으로 바뀝니다.
- 같은 PC 에서 **한 번에 하나만** 돌아갑니다. 이미 실행 중이면 [자동 신청 시작]이 거부됩니다.

> 🔒 보안: 조종판은 `127.0.0.1`(이 PC)에만 바인딩되고, 노션 토큰·카카오 비밀번호를 화면으로 내보내지 않습니다.
> 다른 사이트가 이 화면을 조종하지 못하도록 `Origin` 검사와 JSON 요청만 받는 규칙을 두었습니다.

### 3-2. 검은 창(터미널)로 쓰고 싶을 때 — `scripts\` 안에 있습니다

루트에는 **`run.bat` 하나**만 두고, 예전 실행 파일은 `scripts\` 폴더로 옮겼습니다. 필요할 때만 쓰면 됩니다.

| 파일 | 하는 일 |
|---|---|
| `scripts\run_auto.bat` | 검은 창에서 모드·개수·담당자 열을 골라 실제 신청 |
| `scripts\run_dry.bat` | 실제 신청 없이 오늘 후보 TOP 100 목록만 표로 확인 |
| `scripts\run_login.bat` | 로그인 전용 창(조종판의 [카카오 로그인 창 열기]와 같음) |
| `scripts\run_web.bat` | 웹 조종판만 열기(설치 확인 없이 바로) |
| `scripts\install.bat` | 설치만 따로 다시 하기 |

`scripts\run_auto.bat` 이 물어보는 것:

```
1) 노션 미체크 목록만 불러오기  (신청 안 한 것만)
2) 카카오 전체 중 신청 안 한 것  (인기순/마감임박순, 기본 100개)
3) 노션 설정 변경 (토큰만 넣으면 DB 는 자동으로 찾음 · 처음 한 번만)
4) 웹 조종판 열기
번호를 고르세요 [1/2/3/4] (그냥 Enter = 2):
```

- **1번**을 고르면: **노션 현황표에 이미 등록된 행 중 내 열이 비어 있는 상품만** 신청합니다.
  - 카카오 목록에만 있고 노션에 없는 **신규 상품은 넣지 않습니다.**
  - 노션 행의 `링크`에서 `campaignId` 를 읽어 카카오 목록(모집 중)과 맞춰 보고, **모집 종료·삭제된 상품은 건너뜁니다.**
  - 이미 신청한 상품(신청 이력)·카테고리 기준 제외 상품·카테고리 미확인 상품도 빠집니다.
- **1·2번 모두** 이어서 `몇 개 신청할까요? (그냥 Enter = 100개, 0 또는 '전체' = 전부):` 를 물어봅니다.
- 그다음 **한 번만** 물어봅니다:
  ```
  이번에는 어느 담당자 열에 기록할까요?
    1) 메인.엽   ← 저장된 열(기본)
    2) 1팀.엽2(2200)
    3) 서브.동
   담당자 열 번호 (그냥 Enter = 1번 메인.엽):
  ```
  Enter 만 누르면 **직전에 고른 열**로 바로 진행하고, 다른 번호를 고르면 **그 열을 기억**해 다음부터 기본으로 씁니다.
- **3번**을 고르면: 저장된 노션 설정을 보여 주고 **바꿀 때만** 토큰·DB ID 를 다시 입력받습니다(그냥 Enter = 기존 값 유지).
- **개수 `0`(또는 `전체`) = 제한 없이 지금 신청 대상 전부**입니다.
- 끝나면 **성공/스킵/실패 요약**, **노션 기록 건수**, `logs\results_날짜_시간.csv` 결과 파일이 생성됩니다.

> 상품당 처리 순서(사람이 하는 순서와 같습니다)
> **① 상품 상세 → 위시(선물함)에 담기 → ② [선물 체험단 신청하기] → (옵션이 있으면 옵션 선택) →
> ③ 신청 페이지에서 기본 배송지 확인 → 동의 체크 → 5~7초 쉬었다가 [신청 완료하기] → 확인 창 → 결과 확인**

> 옵션이 있는 상품은 반드시 옵션을 골라 `?optionId=`를 붙여 신청 페이지로 들어갑니다.
> (이게 빠지면 카카오 화면에 "체험단에 응모하지 못했어요 / 고객센터로 문의해 주세요"가 뜨고 신청이 안 됩니다.)

> **대기 시간은 [신청 완료하기]를 누르기 직전**에 넣습니다(사람이 신청서를 확인하고 누르는 것과 같은 흐름).
> 신청 후 다음 상품으로 넘어갈 때는 0.5~1초만 쉽니다. 대기 시간은 `--delay-min` / `--delay-max` 로 바꿉니다.

## 4. 노션에 자동 기록하기 (선택)

신청이 **성공**하면 노션 현황표에 자동으로 한 줄 남깁니다.

- 같은 상품은 **새 행을 만들지 않고** 내 참가자 열만 갱신합니다. (링크의 `campaignId` 로 먼저 찾고, 없으면 상품명으로 찾습니다)
- 기록 형식: `상품명·브랜드`(제목) / `링크` / `옵션` / `메커니즘`(`상세→위시→옵션→신청`) / `마감일·모집현황`(`D-3 · 120/10명`) / 내 열 `11/20` (날짜만)
- 이미 오늘 날짜로 적혀 있으면 건드리지 않고, 다른 날짜만 적혀 있으면 **지우지 않고 줄을 바꿔 덧붙입니다.**
- 노션·네트워크 오류가 나도 **신청 자체는 계속**되고, 마지막 요약에 `노션 기록: O건 성공 / X건 실패` 로 알려 줍니다.

### 4-1. 설정은 **딱 한 번** — 이후에는 담당자 열만 고르면 됩니다

**노션 API 토큰만 있으면 됩니다.** DB ID 는 넣지 않아도, 토큰으로 그 통합(Integration)이 연결된 DB 를 찾아 담당자 열이 있는 DB 를 자동으로 고릅니다.
토큰은 `notion_secret.json` 에 한 번 저장되면 **웹 조종판·검은 창(`scripts\run_auto.bat`) 모두에서 다시 묻지 않고 그대로 씁니다.**
바꿀 일이 있을 때만 웹 조종판의 **▸ ⚙ 설정 변경** 또는 아래 명령으로 들어갑니다(그냥 Enter = 기존 값 유지).

**① 자동으로 만들기 / 바꾸기 (권장)** — 웹 조종판의 **▸ ⚙ 설정 변경** 에서 [저장], 또는 `scripts\run_auto.bat` → `3)`, 또는

```bat
python main.py --setup-notion
```

1. 노션 통합 토큰을 붙여넣습니다. (`https://www.notion.so/my-integrations` 에서 발급)
2. DB ID 는 **그냥 Enter** — 토큰으로 연결된 DB 를 찾아 자동으로 고릅니다. (직접 넣고 싶으면 32자리 ID 나 노션 페이지 주소를 붙여넣어도 됩니다)
3. 그러면 **그 DB에 실제로 있는 참가자 열 목록이 번호로 뜹니다.**
   ```
   1) 메인.엽
   2) 1팀.엽2(2200)
   3) 서브.동
   ...
   번호 (그냥 Enter = 1번 메인.엽):
   ```
   번호만 고르면 `notion_secret.json` 에 저장되고 바로 쓸 수 있습니다.

> 노션 DB 화면 오른쪽 위 **⋯ → 연결 → 만든 통합 추가** 를 해 두어야 읽고 쓸 수 있습니다.

**② 메모장으로 직접 만들기** — `notion_secret.example.json` 을 복사해 `notion_secret.json` 으로 이름을 바꾸고 값을 채웁니다.

```json
{
  "enabled": true,
  "token": "ntn_...",
  "db_id": "....",
  "column": "메인.엽"
}
```

- `db_id` 는 비워 둔 채 `token` 만 넣고 웹 조종판 ⚙ 설정 변경에서 **[↻ DB 목록]** 을 누르면 연결된 DB 를 찾아 자동으로 채웁니다.
- `column` 값만 `메인.엽` / `1팀.엽2(2200)` / `서브.동` 등으로 바꾸면 **그 계정 열에 기록**됩니다.
- 실행할 때 `--notion-column "서브.동"` 처럼 파일보다 우선 지정할 수도 있습니다.
- 노션을 쓰지 않으려면 파일을 지우거나 `"enabled": false` 로 두면 됩니다(CSV 저장은 그대로 동작).

> ⚠️ `notion_secret.json` 에는 API 토큰이 들어 있습니다. `.gitignore` 에 등록되어 있어 **깃허브에 올라가지 않습니다.**
> 이 파일을 남에게 보내거나 공개 저장소에 올리지 마세요.

## 5. 어떤 상품을 신청하나요? (필터 기준)

`config.json` 을 메모장으로 열면 직접 바꿀 수 있습니다.

**신청하는 카테고리**
- 식품·디저트 / 디지털·소형가전 / 리빙·생활용품 / 패션·잡화 / 키즈·아동용품 / 캐릭터 굿즈

**신청하지 않는 카테고리**
- 뷰티·화장품(향수·바디 포함), 골프·레저·스포츠
- 신생아·임신·출산 용품, 반려동물(강아지·고양이) 용품, 뷰티가전

**제외 키워드** (상품명에 들어가면 제외)
신생아, 배냇저고리, 딸랑이, 치발기, 젖병, 분유, 아기띠, 임산부, 산모, 수유, 이유식, 기저귀,
반려동물, 강아지, 고양이, 사료, 캣타워, 탈모, 염색, 립스틱, 틴트, 파운데이션, 아이섀도,
선크림, 세럼, 앰플, 마스크팩, 골프, 스포츠, 등산, 헬스 …

**정렬**
- 기본은 **인기순**(신청자 수 많은 순). 마감 임박 순으로 보려면 `--sort deadline` 을 붙입니다.

## 6. 명령어로 직접 실행하고 싶을 때

```bat
python main.py --login
python main.py --logout
python main.py --dry-run
python main.py --limit 100
python main.py --limit 0
python main.py --notion-pending --limit 200
python main.py --limit 10 --sort deadline
python main.py --notion-column "서브.동" --limit 10
python main.py --setup-notion
python main.py --dry-run --max-pages 5
```

| 옵션 | 설명 | 기본값 |
|---|---|---|
| `--login` | 카카오 로그인 후 세션 저장 (데스크톱 창) | - |
| `--login-mobile` | `--login` 과 같지만 모바일(iPhone) 창에서 로그인 | - |
| `--logout` | 저장된 카카오 로그인 세션(쿠키 백업 + 브라우저 프로필)을 지운다 — 다른 계정으로 다시 로그인할 수 있음 | - |
| `--dry-run` | 실제 신청 없이 후보 목록만 출력 | - |
| `--limit N` | 신청할 개수 (`--limit` 을 안 쓰면 실행할 때 물어봅니다) — **`0` 또는 `all` = 제한 없이 전부** | 물어봄(Enter = 100) |
| `--notion-pending` | **노션 DB 에 이미 등록된 행 중** 내 열 체크가 없는 상품만 신청 — 노션에 없는 카카오 신규 상품은 제외 (`--only-notion-unchecked` 도 같은 옵션) | 꺼짐 |
| `--notion-all` | 1번 모드에서 카테고리 기준(제외 카테고리·키워드)까지 무시하고 노션 미체크 행 전부를 대상으로 함 | 꺼짐 |
| `--notion-column "열이름"` | 기록할 참가자 열 (파일의 column 보다 우선) | 파일 값(기본 `메인.엽`) |
| `--ask-column` | 실행 전에 **어느 담당자 열에 기록할지**만 묻기(기본값 = 직전에 고른 열 · `scripts\run_auto.bat` 이 사용) | 꺼짐 |
| `--setup-notion` | 노션 연동 설정(notion_secret.json)을 대화형으로 만들고 종료 | - |
| `--no-notion` | 노션 기록을 끄고 CSV 만 저장 | 꺼짐 |
| `--sort popular\|deadline` | 인기순 / 마감임박순 | popular |
| `--max-pages N` | 목록을 몇 페이지까지 읽을지(1페이지=50개) | 30 |
| `--delay-min` / `--delay-max` | **[신청 완료하기] 클릭 직전** 대기 시간(초) | 5.0 / 7.0 |
| `--include-unknown` | 카테고리 정보가 없는 상품까지 신청 (기본은 보류) | 꺼짐 |
| `--skip-wishlist` | 상품을 위시(선물함)에 담는 단계를 건너뜀 | 꺼짐(상세에서 담기) |
| `--headless` | 창 없이 실행 | 꺼짐 |

> 자동화·배치에서는 `python main.py --notion-pending --limit 100` 처럼 인자를 주면 **아무것도 묻지 않고** 바로 실행됩니다(토큰·DB ID·담당자 열 모두 저장된 값 사용).
> 사람이 고를 때만 `--ask-column` 을 붙이면 담당자 열 하나만 묻습니다.
> 전부 신청하려면 `--limit 0` (또는 `--limit all`) 을 주세요 — 0/all 은 '지금 대상 전체(제한 없음)'를 뜻합니다.

## 7. 잘 안 될 때

| 증상 | 원인 / 해결 |
|---|---|
| `로그인 세션이 없습니다` | 조종판의 **[카카오 로그인 창 열기]** (또는 `scripts\run_login.bat`) |
| 체험단 화면에서 자꾸 로그아웃 / 로그인 버튼이 "카카오톡 앱에서 보기"로만 뜼 | 모바일 화면의 로그인은 카카오톡 앱 전용입니다. **[카카오 로그인 창 열기]**(데스크톱 창)으로 로그인하세요. |
| `로그인이 확인되지 않았습니다` + `HTTP 401` | 로그인 화면에서 로그인을 끝까지 마치지 않은 경우입니다. 출력된 `현재 브라우저 주소`가 `accounts.kakao.com` 이면 로그인 미완료입니다. |
| `[경고] 신청 화면(모바일 모드)에서 세션이 인식되지 않습니다` | `python main.py --login-mobile` 로 모바일 화면에서 로그인하세요. |
| `신청 버튼을 찾지 못함` | 카카오가 화면을 바꾼 경우입니다. `logs\fail_*.html` 파일이 생깁니다 → 알려 주시면 바로 고칩니다. |
| 팝업 `체험단에 응모하지 못했어요 / 고객센터로 문의해 주세요` | 신청 요청이 서버에서 거부됐습니다. ① 그 상품에 **옵션**이 있는데 옵션 없이 신청된 경우(사유에 `옵션 없음`으로 표시) ② 이미 신청했거나 모집이 끝난 경우 ③ 카카오가 잠시 요청을 막은 경우(연속 신청·자동화 차단)입니다. 사유의 `신청 응답 <status>` 와 `logs\last_apply_request.json` 을 보면 서버 응답이 남습니다. |
| `이미 신청한 체험단` 만 계속 뜼 | 로그인하면 신청 이력까지 걸러집니다. **[카카오 로그인 창 열기]** 로 다시 로그인해 보세요. |
| 목록이 0개 | 인터넷 연결 확인. 카카오가 API 주소를 바꾼 경우도 있습니다. |
| `PC 제한 화면으로 이동` | 모바일 설정이 빠진 경우입니다. 프로그램을 최신 버전으로 받아 주세요. |
| `브라우저(크로미움)가 설치되지 않았습니다` | `run.bat` 을 다시 실행하면 자동으로 내려받습니다(또는 `scripts\install.bat`). |
| `노션 기록: 0건 성공 / N건 실패` | `notion_secret.json` 의 토큰·DB ID 를 확인하고, 노션 DB 화면 **⋯ → 연결** 에 통합이 추가돼 있는지 보세요. 실패 사유(HTTP 401/404 등)가 함께 출력됩니다. |
| `1번 모드(노션 미체크만)는 노션 설정이 필요합니다` | `python main.py --setup-notion` 으로 먼저 설정하세요. |
| 1번 모드에서 대상이 0건 | 노션 DB 의 미체크 행 중 **지금 모집 중인 상품**만 대상입니다. `--dry-run` 출력의 `모집 종료·삭제 N건`·`카테고리 기준 제외 N건` 을 보세요. |
| `웹 조종판` 창이 안 열린다 | 주소 `http://127.0.0.1:8765` 를 브라우저에 직접 입력해 보세요. `[WinError 10048]` 이 나오면 이미 실행 중이거나 다른 프로그램이 포트를 쓰는 중입니다 → `python web_ui.py --port 9000` |
| `웹 조종판` 에서 로그인이 안 됨 | 상단 [카카오 로그인 창 열기]로 데스크톱 창에서 로그인을 끝까지 마쳐 주세요. 끝난 뒤 [로그인 확인]. |
| 다른 계정으로 바꾸고 싶다 | 상단 **[카카오 로그아웃]** → **[카카오 로그인 창 열기]**. 세션이 새로 저장됩니다. 바꾼 뒤 배지에 ``로그인됨 · 닉네임`` 이 새 계정으로 표시되는지 확인하세요. |
| 계정을 바꿨는데 “이미 신청” 건수가 예전 계정 그대로다 | v2.5 에서 고쳤습니다. 세션 파일(`kakao_state.json`)이 바뀌면 프로그램이 **새 쿠키로 다시 읽습니다**. 그래도 그대로면 최신 버전으로 바꾸고 조종판을 껐다 켜 주세요. |
| 배지에 `계정 이름 확인 불가` | 로그인은 됐지만 gift 헤더 API 에서 닉네임을 못 읽은 경우입니다(신청·이력 조회는 그대로 동작). [로그인 확인]을 한 번 눌러 보세요. |
| 노션 행이 두 줄 생겼다 | 같은 상품의 링크(`campaignId`)가 다르게 저장된 경우입니다. 링크가 같은 행은 자동으로 한 줄만 유지됩니다. |
| 신청은 됐는데 `불확실` | 결과 확인만 실패한 경우입니다. 선물하기 앱 → 체험단 → **신청내역**에서 확인하세요. |

## 9. 알아 둘 점 (꼭 읽어 주세요)

- 이 프로그램은 **본인 계정 1개**로만 쓰도록 만들어졌습니다. 여러 계정을 돌리거나 짧은 시간에 반복 실행하면 카카오 이용 제한을 받을 수 있습니다.

**로그인 구조 (2026-11-20 실측)** — `run_login` 이 데스크톱 UA 를 쓰는 이유

- gift 인증 서비스(`chunk-ZOOQ4WOZ.js`): `login()` 은 `isKakaotalk || isMobileOrTablet` 이면 `loginApp()`,
  아니면 `getWebAuthUrl()` 로 갈라집니다. 모바일 UA 에서는 `/giftbox-redirect`(카카오톡 앱 안내)로 빠지고,

  gift 세션을 만들지 못합니다(→ 체험단 페이지는 계속 로그아웃).
- 웹 로그인(=gift 세션 발급) 경로:
  `https://shopping-userauth-web.kakao.com/login?channel=GIFT&redirect_url=<enc(https://gift.kakao.com/a/v1/web/login?redirectUrl=<enc(대상)>)>`
  → `kauth.kakao.com/oauth/authorize?client_id=98020c3772c56cf7faa6aceb97b0722d&redirect_uri=…/callback&state={redirectUrl,channel:GIFT}`
  → `accounts.kakao.com/login?continue=<kauth>` → 로그인 후 `gift.kakao.com/a/v1/web/login` → 세션 쿠키 발급 → 대상 페이지로 복귀
- 위 체인은 UA 와 무관하게 동작하지만, 화면·안내가 데스크톱 기준인 쪽이 로그인이 확실해 `run_login` 만 데스크톱 UA 로 열고
  쿠키는 같은 `kakao_profile` 에 저장해 모바일 UA 신청 단계에서 그대로 사용합니다(쿠키는 UA 와 무관).
